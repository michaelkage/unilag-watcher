A small watcher with a very specific job

Know when
UNILAG changes.

UNILAG Watcher checks public WordPress feeds for new posts and amended posts, then sends the differences to Telegram. This manual follows the implementation in main—not an imagined product roadmap.

Operational briefFour RSS sources. Stable post identity. SHA-256 content fingerprints. Telegram delivery. A JSON state file committed by GitHub Actions. No database, queue service, or runtime package dependencies.

01 — Mental model

It watches posts, not pages.

The unit of tracking is a WordPress post. A post can keep the same identity while its slug or content changes. The watcher stores the last fingerprint for each post ID, per feed, and compares the next observation against it.

IDENTITY

Stable post key

It looks for ?p=NNNNN in the RSS guid first, then the link. If neither has an ID, it falls back to the link, then a title fingerprint.

CHANGE

Content fingerprint

HTML is reduced to text, whitespace is collapsed, and the title is appended. SHA-256 is truncated to the first 16 hexadecimal characters.

DELIVERY

Telegram message

New and updated posts are rendered as HTML messages. Up to three discovered PDF links are included for each post.

MEMORY

Repository state

state.json records hashes and first/last-seen timestamps. GitHub Actions commits it after a successful run.

Important distinction. The README describes the current baseline behavior on main. A separate open pull request, #1 — priority deep-polling, proposes fetching older articles and checking linked PDF bytes. That work is not part of main yet, so it is deliberately not represented as shipped behavior here.
02 — Execution path

One scheduled run, end to end.

The scheduled workflow starts Node 20, checks that Telegram credentials exist, runs the watcher, and commits a changed state file. The schedule is configured as 7,17,47 * * * *—three times an hour, not every 30 minutes.

04 — Persistence

State is the memory.

state.json is not a database. It is a versioned JSON snapshot keyed by source ID, then post ID. Each entry stores a fingerprint plus first-seen and last-seen timestamps.

// Simplified shape from state.json { "version": 1, "lastChange": "2026-10-02T20:44:11.319Z", "sources": { "exam-timetable": { "url": "https://unilag.edu.ng/search/exam+timetable/feed/rss2/", "seen": { "80123": { "hash": "0197e57879b6c144", "firstSeen": "2026-10-02T20:04:12.988Z", "lastSeen": "2026-10-02T20:44:11.319Z" } } } } }
RETENTION

180 days

Entries older than 180 days since lastSeen are pruned. Entries with missing or invalid lastSeen timestamps are retained by the current helper.

NO-OP WRITES

Quiet means quiet

If there are no changes and no pruned entries, the watcher avoids rewriting state.json, preventing empty commits on every poll.

Failure and retry semantics

A failed source fetch leaves that source's state unchanged so the next run can retry it. The watcher sends all generated chunks before writing the new snapshot. If a Telegram send throws, execution stops before the state write, so the changes are eligible to be retried on the next run.

Delivery nuance: this is retry-by-not-advancing-state, not a durable per-message queue. If an earlier chunk or source was delivered and a later send fails, the earlier alert can be sent again on the next run. Telegram's HTTP response is checked for HTTP success; the current code does not separately inspect Telegram's JSON ok field.

Seed mode records the current feed contents as the baseline without sending alerts. This is useful after initial setup, when the existing feed window would otherwise produce a burst of first-run notifications.

05 — Notifications

Telegram is the output channel.

The bot sends HTML-formatted messages to one configured chat. The message includes the source label, a NEW or UPDATED marker, the post title linked to its permalink, and up to three direct PDF links extracted from the RSS item.

# Required GitHub Actions secrets TELEGRAM_BOT_TOKEN = "your BotFather token" TELEGRAM_CHAT_ID = "your numeric chat ID" # Local run example node --env-file=.env watch.mjs --dry-run

Message splitting

Telegram's message cap is 4,096 characters. The watcher packs whole post entries into chunks capped at 3,800 characters, leaving headroom. It does not split an individual entry across messages; an unusually large single entry can still exceed the safe target.

PDF handling in main means link extraction and inclusion in the alert. It does not download the PDF, inspect its bytes, or detect a replacement file behind an unchanged URL. Those capabilities are proposed separately in PR #1.
06 — Runbook

Install, configure, verify.

Requirements

Node.js 20 or newer. The repository has no runtime npm dependencies; parsing, hashing, file I/O, and HTTP requests use Node's built-in APIs.

git clone https://github.com/michaelkage/unilag-watcher.git cd unilag-watcher # Inspect changes without sending or writing state npm run dry # Run the unit suite npm test # Record a baseline, without notifications npm run seed # Send real Telegram notifications (requires env secrets) npm run watch

First-time Telegram setup

  1. Create a bot with @BotFather and copy its token.
  2. Open the bot and press Start so it can message you.
  3. Get your numeric chat ID using the Telegram Bot API getUpdates endpoint.
  4. Add TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID under GitHub → Settings → Secrets and variables → Actions.
  5. Run npm run seed locally and commit the resulting state.json, or trigger a seed run in an appropriately configured local environment.
  6. Use Actions → UNILAG Watcher → Run workflow to verify the scheduled path.
When either secret is missing, the workflow skips the watcher step and emits a warning annotation. This is intentionally a green no-op—not evidence that feed monitoring or Telegram delivery succeeded.

07 — Boundaries

Know what it cannot see.

01 / SOURCE COVERAGE

RSS window only

UNILAG feeds expose roughly the most recent ten posts. Baseline polling cannot see an edit after a post leaves the feed.

02 / PORTAL ACCESS

Public pages only

portal.unilag.edu.ng returns 403 to non-browser clients. Portal-gated information is outside this watcher's reach.

03 / TLS

Apex domain required

The README records a broken certificate on www.unilag.edu.ng; configured feeds use unilag.edu.ng.

04 / FEED SEARCH

Some noise is expected

Timetable and deadline feeds are WordPress search feeds. Empty keyword filters favor recall over precision and can include loosely related posts.

05 / PARSING

Purpose-built RSS parsing

The parser uses regular expressions for RSS item/tag extraction and HTML tag stripping. It is not a general XML or HTML parser.

06 / DELIVERY

One Telegram destination

The current configuration supports one bot token and chat ID. There is no user dashboard, preference center, or multi-recipient routing.

Not an official UNILAG service. This tool monitors public pages and can miss changes outside its sources or feed windows. Treat Telegram alerts as useful signals, then open the linked official post/PDF and verify important academic information directly.
